# Пайплайн агентов

В проекте используется agent pipeline для автоматизации разработки через GitHub Issues.

## Роли

| Роль | Назначение |
|------|------------|
| **analyst** | Анализ issue, план реализации, список документации |
| **developer** | Реализация, PR с `Fixes #<номер>` |
| **QA** | Проверка по чеклисту этапа |

## Метки

- `ready-for-dev` — issue готов к разработке
- `feature` / `bug` — тип задачи
- Метки пайплайна выставляет оркестратор

## Контракт разработчика

1. Ветка `issue/<номер>-краткое-имя` от актуального `main` (или от head PR родителя).
2. PR с строкой `Fixes #<номер>` в теле; не затирать существующие ссылки на issues.
3. Документация обновляется в том же PR по списку аналитика.
4. После этапа — `[x]` в `docs/MVP_PLAN.md`. MVP закрыт (этапы 0–6); новые этапы — только если явно расширяется scope.
5. Не мержить в `main`, не деплоить, не коммитить секреты.

Подробные инструкции для агентов — в `AGENTS.md`.
