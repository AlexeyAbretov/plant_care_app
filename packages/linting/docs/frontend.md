# Шаблон frontend

Общие соглашения для frontend (Vite, React, TypeScript). Каталоги `components/`, `pages/` и остальные лежат в `src/` или в корне проекта. Домен приложения — названия экранов, формулы, env — в конституции репозитория, не здесь.

Правила Cursor с тем же смыслом: `cursor/react/`. После правки этого файла или `cursor/` в потребителе выполните синхронизацию из корня репозитория:

```bash
npm run sync-cursor
```

В чужом проекте, где пакет стоит из npm или `file:`:

```bash
node node_modules/@llm/linting/scripts/sync-cursor.js
```

`globs` стори, типов, запрета API и запрета импорта контейнеров в `components/` ищут `components/`, `pages/`, `containers/` и `hooks/` на любой глубине. Стрелки и баррели действуют на любые `*.ts` и `*.tsx`. Каталог `apps/web` не требуется.

## Слои

| Каталог | Назначение |
|---------|------------|
| `pages/` | Экраны маршрутов |
| `components/` | Переиспользуемый UI |
| `containers/` | Данные и хуки, без собственной вёрстки |
| `api/` | HTTP-клиент и REST |
| `hooks/` | React-хуки |
| `types/` | Общие доменные типы |
| `utils/` | Код с несколькими потребителями вне одного компонента |

Баррель слоя — `index.ts` в корне каталога (`components/`, `utils/`, `services/`, `store/` и любого другого). У каждого подмодуля свой `index.ts`.

## Функции

Именованные и экспортируемые функции — стрелочные в любом модуле (`utils`, `services`, `store`, компоненты). Вложенные обработчики — `const handleX = async () => {}`. Методы классов остаются методами.

Линтер: `createWebConfig` из `@llm/linting/web` (`func-style: expression`, алиасы корневых каталогов `src`, Storybook `flat/recommended`). `createConfig` для API по-прежнему требует `function` и плагин Storybook не загружает.

## Импорты

Алиасы (`tsconfig`, Vite): `@api`, `@components`, `@config`, `@containers`, `@hooks`, `@pages`, `@types`, `@utils` → соответствующие каталоги в `src/` (или `config.ts`).

- Между корневыми каталогами `src` — только алиасы.
- Подмодуль снаружи его папки импортируют только через баррель — любой каталог, не только UI: `utils`, `providers`, `services`, `store` и остальные. Другой слой — алиас слоя (`@utils`, `@services`, …), не `@utils/date`. Сосед в том же слое — путь к папке (`../session`), это её `index.ts`, не внутренний файл.
- Внутри папки — относительные `./`. Стори и тесты этой папки импортируют модуль относительно (`../Name`).
- Относительные импорты без суффикса `.js`.

## Контейнеры

`containers/Name/Name.tsx` + `index.ts`, публичный реэкспорт через `containers/index.ts`.

Контейнер подключает хуки и передаёт пропсы в UI-компонент. `components/` не импортирует `@containers`. Контейнер передают снаружи через `children`, слот `ReactNode` (`headerExtra`) или render prop (`renderHeader`). Собирает его страница или корень приложения.

## Компоненты не вызывают API

Каталог `components/` не обращается к backend, не собирает его URL и не импортирует `@api`. Вызовы REST и разбор ошибки API живут в `pages/`, `hooks/` и `containers/`. Компонент получает результат снаружи:

- действие — колбэк;
- адрес картинки — готовая строка;
- текст сбоя колбэка — `Error.message`, иначе своя заглушка.

## Колокация

Рядом с компонентом, страницей или контейнером:

| Файл | Содержимое |
|------|------------|
| `Name.utils.ts` | Чистые функции этого модуля |
| `Name.types.ts` | Пропсы и локальные типы. Пустой файл не заводят |
| `Name.css` | Стили этого компонента |

Внутри папки — относительный импорт. В баррель реэкспортируют только то, что нужно снаружи (утилиты для страниц, публичные типы). Пропсы в баррель не выносят. Вложенные компоненты той же папки делят файл типов родителя.

Общие доменные модели остаются в `types/`. Глобальный `index.css` — только сброс страницы.

## Стори (Storybook)

У каждого компонента в `components/` есть стори: `Name/__stories__/Name.stories.tsx`.

- Импорт компонента — относительный (`../Name`). В баррель стори не реэкспортируют.
- CSF3: `satisfies Meta<typeof Name>`, стори — именованные экспорты. `title` — `Components/Name`.
- Минимум одна стори. Отличимые состояния UI — отдельные стори.
- Общие провайдеры — в `.storybook/preview.tsx` рядом с исходниками frontend.

## Unit-тесты (Vitest)

Тесты лежат в `__tests__` того артефакта, который проверяют. В баррель их не реэкспортируют. Импорт проверяемого модуля — относительный.

- Раннер — Vitest (`jsdom`), запросы к DOM — Testing Library.
- Отображение компонентов, контейнеров и страниц — снапшотами. Клиенты API, хуки и утилиты — утверждениями на вызовы и возвращаемые значения.
- В покрытие входят каталоги слоёв: `api`, `components`, `containers`, `hooks`, `pages`, `utils`. Не входят `*.types.ts`, баррели `index.ts`, `__stories__` и `__tests__`.
- Порог веток — 80%. Строки, операторы и функции — 100%: в HTML-отчёте не должно оставаться красных непокрытых строк.

## Что остаётся в проекте

- Дерево конкретных экранов и компонентов, маршруты, локаль, env.
- Доменные формулы и лимиты.
- Правила Cursor, которых нет в `cursor/` этого пакета: скрипт синхронизации их не удаляет.
